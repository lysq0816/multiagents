# 第 8 天：离线实验矩阵

第 8 天完成了一个可重复运行、零模型调用、零业务写操作的架构控制流实验。它比较四种架构如何处理相同的售后场景卡：

1. `single_agent`：单一处理者直接判断；
2. `fixed_multi_agent`：每个任务都固定经过三个逻辑角色；
3. `routed_multi_agent`：普通任务走短路径，复杂任务进入协作；
4. `routed_multi_agent_with_audit`：在路由多智能体后增加无工具权限的独立审核。

## 任务集

固定清单位于 `benchmarks/retail_day8_tasks.json`，共 30 个任务：取消、退货、换货各 10 个。每一类都包含正常业务，以及缺少信息、政策冲突、多订单、证据错配、参数错配、重复动作等场景。

这 30 个任务是本项目的离线确定性故障注入任务，不是官方 τ2 任务，也不能替代真实 LLM 或官方 τ2 实验。

## 运行

在项目根目录执行：

```powershell
uv run python scripts\run_day8_experiment.py
```

默认每个任务在每种架构下重复 3 次：

```text
30 个任务 × 4 种架构 × 3 次 = 360 条运行记录
```

也可以增加重复次数，但不能低于 3：

```powershell
uv run python scripts\run_day8_experiment.py --repetitions 5
```

输出文件：

- `artifacts/day8/experiment_report.json`：全部逐次结果和按架构、意图聚合的指标；
- `artifacts/day8/experiment_report.md`：便于阅读的汇总表。

JSON 报告还记录生成时间、任务清单的 SHA-256 摘要和实验代码版本，便于确认两次报告
是否基于同一份任务定义。由于生成时间本身会变化，复现实验时应比较任务摘要、逐次运行
记录和聚合指标，而不是要求整个 JSON 文件逐字节相同。

## 指标口径

- 成功率/最终状态正确率：架构给出的安全处置是否等于任务卡的确定性预期；
- 政策违规：本应澄清、拒绝或转人工的任务却进入批准候选；
- 未授权写：始终为 0，因为实验运行器没有任何业务写工具；
- 转人工率：结果为 `human_handoff` 的比例；
- 智能体调用：逻辑工作流角色调用次数，不是 LLM API 调用；
- 工具调用：确定性的只读工具预算；
- 延迟：根据角色与只读工具操作数计算的确定性代理值，不是墙钟或模型延迟；
- 一致性：同一架构与任务的重复结果签名是否完全相同；
- token/成本：模型调用为 0，因此 token 和模型成本保持 `null`，不会伪造估算值。

## 安全边界

该实验不读取 API Key，不访问网络，不调用模型，不调用 τ2 环境，也不执行取消、退货或换货写操作。报告中的政策违规表示控制流没有及时拦截候选动作，并不表示订单真的被修改。

## 测试

```powershell
uv run pytest tests\test_experiment_matrix.py -q
```

测试覆盖清单平衡、360 单元完整性、最少三次重复、结果一致性、零模型用量、零写操作、独立审核拦截能力、路由调用节约，以及 JSON/Markdown 报告生成。
